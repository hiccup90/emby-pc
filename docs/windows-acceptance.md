# Emby PC · Windows 实机验收清单

> 文档：docs/windows-acceptance.md · 版本 v1.0 · 2026-11-04 · 维护：release-engineer（T9）
> 适用构建：0.1.1-rc（M1 播放内核 + M2/M3 UI + Qt 控制条），Windows 10/11 x64
> 用途：用户在 Windows 实机上按步骤验收「播放内核 + 日志 + 打包产物」；每条都有操作、预期和记录方式。
> 判定规则：**所有 P0 条目 PASS 才算通过**；FAIL 必须附「截图 + app.log + mpv.log + 发生时间」。

---

## 0. 验收前准备

### 0.1 机器与环境

| 项 | 要求 | 备注 |
|---|---|---|
| 操作系统 | Windows 10 22H2 或 Windows 11 23H2，x64 | 记下系统版本（winver） |
| GPU | NVIDIA / Intel / AMD 任一，支持 D3D11VA | 记下显卡型号与驱动版本 |
| Qt | Qt 6.5+（MSVC 2022 x64 或 MinGW 构建） | 只用于源码构建；用发布 zip 则不需要 |
| CMake | 3.21+ | 只用于源码构建 |
| 7-Zip | 可选 | 仅 fetch-libmpv.ps1 解压 .7z 时需要（Windows 自带 tar 可兜底） |
| 显示器 | 1920×1080 或更高；多显示器/高 DPI 加分 | 窗口验收项需要 |

### 0.2 测试素材（S1~S5）

| 编号 | 类型 | 规格 | 用途 |
|---|---|---|---|
| S1 | HDR10 | 4K HEVC 10bit，BT.2020/PQ，≥40Mbps | 不发灰、颜色正确 |
| S2 | 杜比视界 P5 | 4K Profile 5（IPTPQc2） | 不绿屏/紫屏 |
| S3 | 杜比视界 P8 | Profile 8.1 与 8.4 各一个 | 不绿屏、可正常播放 |
| S4 | ASS 特效字幕 | pos/move/t/fad/clip、卡拉 OK、嵌入字体、中英双语 | 字幕样式/字体/位置 |
| S5 | SDR 基准 | 1080p H.264/HEVC，24fps | 冒烟/回归基准 |

> 没有对应素材时，对应条目记 **BLOCKED**（缺素材），不要记 PASS。

### 0.3 构建产物（二选一）

**方式 A：用现成发布包（推荐给验收人）**

1. 拿到 `dist\emby-pc-<版本>-win64.zip`。
2. 解压到不含中文和空格的路径，例如 `D:\Test\emby-pc-0.1.1-win64\`。
3. 确认目录内有 `emby-pc.exe`、`libmpv-2.dll`、`platforms\qwindows.dll`。

**方式 B：从源码构建 + 打包（给开发/构建验证）**

```powershell
# 在仓库根目录（含 app\ 的目录）执行
cd <repo>

# 1) 获取 libmpv（把 <URL> 换成 shinchiro 发布页里 mpv-dev-x86_64-*.7z 的下载地址）
powershell -ExecutionPolicy Bypass -File app\scripts\fetch-libmpv.ps1 -Url "<URL>"

# 2) 构建 Release 并打包（Qt 路径按本机实际改）
powershell -ExecutionPolicy Bypass -File app\scripts\package-windows.ps1 -QtPrefix C:\Qt\6.8.0\msvc2022_64

# 产物：dist\emby-pc-0.1.1-win64.zip（同时保留 dist\emby-pc-0.1.1-win64\ 免安装目录）
```

> 如果 `fetch-libmpv.ps1` 访问不了 GitHub，可以先手工下载 `mpv-dev-x86_64-*.7z`，
> 再用 `-Url "D:\Download\mpv-dev-x86_64-*.7z"` 传本地路径。

### 0.4 五分钟快速冒烟（先跑这个）

时间紧时先跑这一轮，任何一步失败就停下收集日志：

1. 启动应用 → 若有登录框点「取消」 → 菜单「帮助 → 打开日志目录」 → 确认目录里有 `app.log`。
2. `文件 → 打开文件…` 选 S5 → 有画面有声 → 鼠标移入出现 Qt 控制条 → 空格能暂停/继续。
3. 按 `i` 打开统计 → `Hwdec` 显示 `d3d11va`（不含 `-copy`）、VO 为 `gpu-next`。
4. 打开 S1 播 2 分钟（不发灰）→ 打开 S2 播 2 分钟（不绿屏）。
5. 按 `f` 全屏 → `Esc` 退出；关闭应用 → 回日志目录确认已生成 `mpv.log`。

## 2. 日志与诊断（L 组）

> 这是本任务的重点：日志必须可被用户一键找到、一键打包回传。

| 编号 | 操作步骤 | 预期结果 | 记录方式 |
|---|---|---|---|
| L-01 | 菜单「帮助 → 打开日志目录」 | 资源管理器打开日志目录。Windows 下通常为 `%LOCALAPPDATA%\emby-pc\emby-pc\`（以实际打开为准） | 截图：资源管理器地址栏 + 目录内容 |
| L-02 | 查看目录内 `app.log` | 文件存在且非空；每行格式为 `时间 [级别] [分类] 内容`（Debug 构建还会附 `(源文件:行)`）；包含版本、Qt 版本、系统、日志路径等启动信息 | 截图/复制 app.log 前 20 行 |
| L-03 | 打开一个本地视频（见第 3 节），再回日志目录 | 目录内新增 `mpv.log`；退出应用后文件仍有内容（已 flush） | 截图：目录内容 + mpv.log 前 20 行 |
| L-04 | 用文本编辑器打开 `mpv.log` | 首部包含 mpv 版本信息（形如 `[cplayer] mpv 0.xx.x`）与 `VO: [gpu-next]`、`hwdec`、`gpu-api` 等启动日志 | 复制 mpv.log 前 60 行，标出 mpv 版本行 |
| L-05 | 敏感信息检查：对 app.log 和 mpv.log 执行搜索 `findstr /i "access_token api_key password authorization" app.log mpv.log` | **不得出现**真实 token、密码、Authorization 头内容（出现即 P0 安全缺陷；把命中行打码后报回） | 命令行输出截图（敏感值打码） |
| L-06 | 关闭应用，把整个日志目录复制到 `acceptance-<日期>-<机器名>\logs\` | 目录里至少有 `app.log`；播放过则还有 `mpv.log`；如有 `app.log.1/.2` 一并保留 | 最终交付 zip 中体现 |
| L-07 | 凭据存储检查（升级场景：**先在 0.1.0 登录并保持**，再覆盖安装 0.1.1 并启动一次） | cmd 执行 `reg query "HKCU\Software\emby-pc\emby-pc\auth" /s`：只看到 `profile.dpapi.v1`（QSettings 以 REG_SZ 存 base64 的 DPAPI blob，不是裸二进制），**没有** `profile` 明文值；重启后登录态可恢复（服务器可达时）；`%LOCALAPPDATA%\emby-pc` 仅用于 app.log/mpv.log；Linux 回退密文在 `$XDG_CONFIG_HOME/emby-pc/emby-pc/secure/profile.dat`（0600） | 命令行输出截图（敏感值打码）+ 升级前后对比 |

> 说明：`mpv.log` 只有**真正初始化 libmpv（打开文件播放）之后**才会生成；只启动不播放时没有该文件是正常的。
> 如果启动阶段就失败，先收集 `app.log`（如不存在，检查 `%LOCALAPPDATA%\emby-pc\emby-pc\` 是否被安全软件拦截）。

|---|---|---|---|
| S-01 | 播放 S5（1080p SDR），按 `i` 打开统计 | 统计面板显示分辨率、视频/音频编码、帧率、丢帧数等 | 截图：完整统计面板 |

## 7. 日志与截图收集（最终交付）

1. 完成以上所有项目后，**先不要卸载或覆盖安装**。
2. 菜单「帮助 → 打开日志目录」，确认目录内有 `app.log`（播放过还应有 `mpv.log`，以及可能的 `app.log.1/.2`）。
3. 关闭应用（让日志 flush 到磁盘）。

5. 截图统一放到 `acceptance-<日期>-<机器名>\screenshots\`，命名规则见第 5 节。
6. GPU 证据：播放 4K 时任务管理器 → 性能 → GPU，引擎下拉选「3D」「Copy」「Video Decode」各截一张，命名 `GPU-3D.png` / `GPU-Copy.png` / `GPU-VideoDecode.png`。
7. 填写第 8 节结果汇总，连同 `logs\` 与 `screenshots\` 打成一个 zip：
   `acceptance-<日期>-<机器名>.zip`。
8. 回传 zip 时附：Windows 版本（winver）、GPU 型号/驱动版本、测试人、开始/结束时间。

## 9. 验证边界说明（重要）

1. **Linux 容器只能做编译/语法验证**：本仓库的 `scripts/build-linux.sh` 已在 Debian 13 + Qt 6.8 容器内验证 `cmake` 配置与全量编译通过；`--wid` 嵌入、D3D11VA 硬解、HDR/DV tone-map、Qt 控制条、窗口贴边等**只能在本清单的 Windows 实机上验证**。
2. **PowerShell 脚本未在容器内执行过**（容器没有 Windows/PowerShell）：`package-windows.ps1` 与 `fetch-libmpv.ps1` 按 PowerShell 5.1 语法编写，并做了静态检查；首次运行若报语法/参数错误，请把完整报错（含命令行）贴回，我们会按 Windows 实际环境修正。
3. **mpv.log 依赖真实 libmpv 加载**：没有 `libmpv-2.dll` 或 libmpv 初始化失败时不会生成；此时以 `app.log` 中的错误信息为准。
4. `package-windows.ps1` 需要本机已安装 Qt 的 `windeployqt.exe`；脚本会给出缺少 Qt/libmpv 的明确错误，不会静默产出残缺包。
5. 当前 UI 的媒体库/登录仍是 M2 早期实现（mock/部分登录流程）；本清单聚焦播放内核、日志、窗口与打包。登录/服务器/媒体库的完整验收在 M2-A/M2-B 任务完成后补充。
